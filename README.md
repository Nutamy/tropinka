# Тропинка — лендинг (Cloudflare Pages)

Статический сайт + одна serverless-функция (Cloudflare Pages Functions), которая
пересылает заявки из формы на сайте в Telegram. Внешних зависимостей и сборки нет —
это чистые HTML/CSS/JS, деплой заключается в загрузке папки как есть.

## Структура всего проекта

```
tropinka-landing/
├── index.html              — весь лендинг (одна страница)
├── css/styles.css          — UI Kit: палитра, типографика, компоненты
├── js/main.js               — WhatsApp-ссылки, мобильное меню, отправка формы
├── functions/api/submit.js  — Cloudflare Pages Function: форма → Telegram
├── images/                  — логотип, favicon и фото галереи «Жизнь центра»
├── _headers                 — базовые security-заголовки и кеширование
└── README.md
```

## 1. Деплой на Cloudflare Pages

1. Залейте эту папку в Git-репозиторий (GitHub/GitLab) — Cloudflare Pages
   деплоится из репозитория. Либо используйте прямой деплой через `wrangler`:
   ```bash
   npx wrangler pages deploy tropinka-landing --project-name=tropinka
   ```
2. В Cloudflare Dashboard → **Workers & Pages → Create → Pages** подключите
   репозиторий. Build command — оставить пустым, output directory — `/`
   (корень проекта, так как сборки нет).
3. Cloudflare сам обнаружит папку `functions/` и поднимет `/api/submit`
   как serverless-функцию — ничего дополнительно настраивать не нужно.

## 2. Настройка Telegram-бота

1. В Telegram напишите **@BotFather** → `/newbot`, задайте имя — получите
   `TELEGRAM_BOT_TOKEN` вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`.
2. Узнайте `TELEGRAM_CHAT_ID`:
   - Если заявки должны приходить лично вам — напишите своему боту любое
     сообщение, затем откройте
     `https://api.telegram.org/bot<TOKEN>/getUpdates` в браузере и найдите
     `"chat":{"id": ...}` в ответе.
   - Если заявки должны приходить в группу — добавьте бота в группу,
     напишите в группе любое сообщение и точно так же посмотрите
     `getUpdates` (id группы будет отрицательным числом).
3. Отправьте боту `/start` (или любое сообщение) до первого теста формы —
   иначе Telegram не разрешит боту писать первым.

## 2.1 Настройка Cloudflare Turnstile (защита формы от спама)

Turnstile — бесплатная антибот-проверка от Cloudflare, невидимая для
большинства посетителей (в отличие от классической капчи с картинками).
Она уже подключена в коде (виджет в форме, проверка токена в
`functions/api/submit.js`) — нужно только получить пару ключей и вставить
их в двух местах.

1. Зайдите в [Cloudflare Dashboard](https://dash.cloudflare.com/) →
   в левом меню **Turnstile** (если раздела не видно — он в общем меню
   аккаунта, не внутри конкретного проекта Pages).
2. **Add widget** (или «Добавить виджет»):
   - **Widget name** — любое понятное имя, например `tropinka-lead-form`.
   - **Domain** — впишите `tropinka.pages.dev` (и свой домен позже, если
     появится).
   - **Widget Mode** — оставьте **Managed** (Cloudflare сам решает,
     показывать ли посетителю визуальную проверку — для большинства это
     останется полностью незаметным).
3. Нажмите **Create**. Cloudflare покажет два значения:
   - **Site Key** — публичный, его видно в HTML-коде страницы, ничего
     страшного.
   - **Secret Key** — приватный, его никому не показывайте и никуда,
     кроме переменной окружения ниже, не вставляйте.
4. **Site Key → в код.** Откройте `index.html`, найдите строку
   (поиском по `cf-turnstile`):
   ```html
   <div class="cf-turnstile" data-sitekey="0x0000000000000000000000AA" ...>
   ```
   замените `0x0000000000000000000000AA` на ваш реальный Site Key.
5. **Secret Key → в Cloudflare Pages.** Dashboard → ваш проект Pages →
   **Settings → Environment variables** → добавьте новую переменную для
   окружения **Production** (и Preview при необходимости):

   | Имя переменной          | Тип    | Значение                              |
   |--------------------------|--------|-----------------------------------------|
   | `TURNSTILE_SECRET_KEY`  | Secret | Secret Key из шага 3                    |

6. Закоммитьте изменённый `index.html` и задеплойте (push в Git — Cloudflare
   передеплоит автоматически, как и раньше).

**Важно про порядок:** пока Site Key в `index.html` остаётся плейсхолдером
`0x0000...`, виджет не отрисуется и токен не сформируется — форма будет
сознательно отказывать в отправке (`turnstile_missing`), а не тихо пропускать
спам. Это специально: лучше форма на секунду перестанет работать и вы это
сразу заметите, чем отправка молча останется без защиты. Поэтому шаги 4 и 5
нужно сделать **до** следующего деплоя, вместе.

**Как проверить, что заработало:** откройте сайт в приватном окне, отправьте
тестовую заявку — если письмо в Telegram пришло и на странице не было ошибки
про антиспам, всё подключено верно. Если видите ошибку — проверьте, что
Site Key в HTML и Secret Key в переменной окружения от одного и того же
виджета (Cloudflare покажет ошибку `turnstile_failed`, если ключи не парные).

## 3. Переменные окружения в Cloudflare

В Cloudflare Dashboard → ваш проект Pages → **Settings → Environment variables**
добавьте для окружения **Production** (и при необходимости Preview):

| Имя переменной          | Тип      | Значение                          |
|---------------------------|----------|------------------------------------|
| `TELEGRAM_BOT_TOKEN`     | Secret   | токен от @BotFather                |
| `TELEGRAM_CHAT_ID`       | Secret   | id чата/группы для приёма заявок   |
| `TURNSTILE_SECRET_KEY`  | Secret   | Secret Key из раздела 2.1 выше     |

После добавления переменных — **Retry deployment** (переменные подхватываются
только новым деплоем).

**Раунд 7** — читаемость и соответствие Impeccable (pbakaus/impeccable):
- Диагноз: почти весь сайт (не только hero) стоял на светло-голубом фирменном
  градиенте `#6AC6ED`, а текст поверх него был белым/светлым. По формуле
  контраста WCAG это ≈1.9:1 при минимуме 4.5:1 для обычного текста — то есть
  системная, а не косметическая проблема. Плюс несколько мест, где насыщенный
  цвет использовался как ЦВЕТ ТЕКСТА поверх другого насыщенного/светлого
  фона: жёлтый акцент в H1 на голубом (~1.3:1), звёзды отзывов `★★★★★`
  жёлтым на белом (~2.1:1), бейдж «Есть места» зелёным на светло-зелёном
  (~2.9:1), надпись `@tropka_log` жёлтым на бирюзовой кнопке (~2.7:1).
  Это прямое нарушение принципа Impeccable «Don't use gray/light text on
  colored backgrounds» — а `text-shadow`, которым местами пытались
  компенсировать контраст на заголовках, сам по себе является тревожным
  сигналом («shadow вместо реального контраста»), тоже не в духе Impeccable.
- **Фон**: `body` вместо сплошного фирменного градиента — белый. По
  официальной палитре роль небесного `#6AC6ED` — «фон бренда, шапка/хедер»,
  то есть он и не задумывался как фон всей страницы; это расширение
  появилось в раунде 3 и оказалось той самой причиной нечитаемости.
  Голубой остался в hero (баннер бренда) — с тёмным текстом поверх вместо
  белого. `#how-it-works`, `#why-us`, `#teachers`, `#location` получили
  еле заметный тон `var(--surface)` для ритма между секциями — вместо
  «всё на одном фоне» / «всё в тенях».
- **Hero**: `h1` — тёмно-чернильный (`--ink`, 6.8:1 на голубом) вместо
  белого; акцентное слово — `--sea-dark` (официальная роль «текст на
  цветном фоне», ≈4:1 на крупном жирном шрифте). Кнопка-призрак
  «Смотреть программы и цены» и адрес под hero — тоже перекрашены с белого
  на чернильный/`sea-dark`.
- **Мелкий текст на цветных подложках** приведён к WCAG AA: добавлены
  «текстовые» тона `--sun-dark` (`#8A6800`, вместо неиспользуемого дефолта
  `#E0A800`) для звёзд рейтинга и `--green-text` (`#1B783A`) для бейджа
  «Есть места», галочки «Подтверждён» и статуса формы — сама насыщенная
  `--sun`/`--green` остаётся на своих ролях (кнопка, фон бейджа), меняется
  только цвет текста поверх светлого тона той же палитры.
- **Прочее из чек-листа Impeccable**: тень в лайтбоксе `rgba(0,0,0,.55)`
  (чистый чёрный — отдельный «don't») заменена на тонированную
  `rgba(11,49,56,.55)`; цифра статистики (`--orange`, 34px) чуть затемнена
  (`#D9631A`), чтобы гарантированно проходить порог 3:1 для крупного текста.
- **Что оставлено намеренно, вопреки «умолчаниям» Impeccable**: pill-радиус
  кнопок/тегов (999px) и радиус карточек (20–24px) — это подтверждённый
  официальный UI Kit клиента, а не гипотеза; сам Impeccable формулирует
  правило «The brief wins» — подтверждённый бренд-кит имеет приоритет над
  дефолтными рекомендациями фреймворка.
- Body `line-height` увеличен с 1.55 до 1.62 (Impeccable: тексту нужен
  «воздух» между строк для комфортного чтения).
- Проверено скриншотами Playwright (desktop 1440px и mobile 390px,
  полная прокрутка) — до/после сравнение показало разницу принципиально:
  текст на голубом фоне, звёзды отзывов и бейдж «Есть места» стали
  отчётливо видны там, где раньше буквально терялись на фоне.

**Раунд 9** — единый формат карточек педагогов (по фидбэку «рамки должны
быть одинаковыми»):
- **Кадрирование фото**: 6 фото педагогов были разного типа (селфи крупным

  автоматическое распознавание лица (OpenCV) с одинаковой долей лица в

- **Высота карточек**: `.teacher-card` переведена на `display: flex;
  flex-direction: column`, `.teacher-info` — на `flex: 1`, а описание

- Проверено скриншотами Playwright на 1440px / 820px / 390px — во всех

  одинаковой высоты, обрезки текста нет.

**Раунд 10** — иллюстрация в hero обрезала детей по краям:
- `.hero-media-card img` был жёстко зафиксирован на `aspect-ratio: 4/3`,
  а сама иллюстрация (`images/hero-illustration.jpg`) — на самом деле
  `1000×584` (~12:7, заметно шире). При `object-fit: cover` в более узкую
  4:3-рамку браузер обрезал края слева и справа — а дети на этой картинке
  стоят почти вплотную к обеим границам кадра, поэтому крайних задевало.
- Первая попытка исправить (просто поменять `aspect-ratio` на `1000/584`)
  не сработала сама по себе: у `<img>` в HTML оставались атрибуты
  `width="700" height="525"` (старые пропорции 4:3), а CSS-правило
  переопределяло только `width`, но не `height` — значит побеждал
  прописанный в HTML `height="525"`, а не `aspect-ratio` в CSS.
  Добавлено явное `height: auto` в CSS-правило и HTML-атрибуты картинки
  обновлены на реальные `width="1000" height="584"` — теперь высота
  действительно считается из `aspect-ratio`, и `object-fit: cover`
  показывает иллюстрацию целиком, без обрезки по бокам.
- Проверено скриншотами Playwright (1440px и 390px) — все дети на
  иллюстрации, включая крайних слева и справа, видны полностью.

**Раунд 15** — оптимизация изображений (WebP/AVIF):

- Для всех 19 фото/логотипа (hero-иллюстрация, 11 фото галереи, 6 фото педагогов, логотип) сгенерированы `.webp` и `.avif`-версии рядом с оригиналами — оригинальные `.jpg`/`.png` не тронуты и остаются универсальным fallback. `favicon.png` и `images/og-image.jpg` намеренно не трогали: favicon должен читаться максимально широким кругом старых браузеров/тулинга, а og-image разбирают краулеры соцсетей с неровной поддержкой AVIF/WebP — оба файла никогда не грузятся в браузере обычного посетителя напрямую.
- `index.html`: каждый `<img>` обёрнут в `<picture>` с `<source type="image/avif">` → `<source type="image/webp">` → исходный `<img src="....jpg/png">` как финальный fallback. Браузер сам выбирает самый лёгкий поддерживаемый формат, разметка/JS-логика (лайтбокс, лениво читающий `data-full`/`data-alt` с кнопки `.bubble`) не менялась.
- Hero-иллюстрация (LCP-элемент) сделана responsive: два размера (700w и 1000w=оригинал) × 2 формата, `sizes="(min-width: 960px) 519px, 100vw"` — 519px подобрано по фактической ширине `.hero-media-card` на десктопе (`--container-max: 1180px`, `hero-grid` колонка 0.95fr). `<link rel="preload">` в `<head>` обновлён на `imagesrcset`/`imagesizes`, указывающие на те же WebP-файлы — браузеры без поддержки WebP просто игнорируют этот preload и подхватывают `.jpg` через обычный парсинг `<picture>`.
- Логотип (используется трижды — шапка, блок «О центре», футер) сконвертирован с сохранением альфа-канала (прозрачный фон).
- Измеренный результат по 19 файлам (сумма байт исходных `.jpg`/`.png` против новых файлов): оригиналы — **1300 КБ**; WebP — **847 КБ (−35%)**; AVIF — **570 КБ (−56%)**. Реальная экономия для конкретного посетителя ещё выше — картинки для узких экранов используют вариант `-700w`, а не полноразмерный оригинал.
- Проверено headless Chromium (Playwright): все `<picture>` реально выбирают `.avif` (`img.currentSrc`), `naturalWidth` у каждой картинки ненулевой (не битые), визуальных регрессий на галерее/педагогах/hero/футере — нет, включая мобильную ширину 390px.

## 7. Локальная проверка перед деплоем

Сайт полностью статический, поэтому для просмотра достаточно любого простого
HTTP-сервера в папке проекта, например:

```bash
npx serve tropinka-landing
```

Функция `/api/submit` работает только на инфраструктуре Cloudflare Pages —
локально проверить полный цикл отправки в Telegram можно через
`npx wrangler pages dev tropinka-landing`.
